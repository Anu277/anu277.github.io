# 02_DESIGN_SYSTEM.md

# Design System

This document defines the complete visual language of the portfolio.

Every UI element must feel like it belongs to the same product.

Users should never feel like different pages were designed independently.

Consistency is more important than creativity.

Every design decision must improve usability before aesthetics.

---

# Design Philosophy

The interface should feel like premium engineering software.

Not a marketing website.

Not a SaaS landing page.

Not a dashboard.

Not a portfolio template.

The interface should communicate:

• Confidence

• Precision

• Engineering Quality

• Simplicity

• Technical Depth

• Product Thinking

The design should remain timeless.

Avoid trends that will look outdated in one year.

---

# Visual Language

Imagine if:

Apple designed an IDE.

Linear designed an AI workstation.

Notion designed a desktop application.

Figma designed a portfolio.

The result should feel:

Minimal.

Industrial.

Modern.

Purposeful.

Every element should have intention.

---

# Color Philosophy

The interface intentionally limits color.

More colors do NOT create a better interface.

Less color creates stronger hierarchy.

The entire website should primarily rely on:

Black

White

Orange

Nothing else.

Orange exists to direct attention.

Not decorate.

If orange becomes the first thing users notice,

the design has failed.

# Typography Philosophy

Typography is the primary visual element.

Not illustrations.

Not gradients.

Not shadows.

Good typography removes the need for decoration.

Text should communicate confidence.

Avoid trendy typography.

Prefer timeless typography.

---

# Font Selection

Primary

Geist

or

Inter

Monospace

JetBrains Mono

or

IBM Plex Mono

Never mix more than two font families.

---

# Typography Scale

Display

Hero Titles

Very large.

Minimal.

Confident.

H1

Project Titles

Large.

H2

Section Titles

Bold.

Clear.

H3

Subsections

Readable.

Body

16–18px

Never below 16px.

Small Text

Only metadata.

Never for primary information.

---

# White Space

Whitespace is content.

Do not fill every area.

Space creates rhythm.

Space creates focus.

Space creates hierarchy.

If removing whitespace makes the page feel busy,

restore it.

---

# Grid System

Desktop

12-column grid

Tablet

8-column grid

Mobile

4-column grid

Align everything.

Avoid arbitrary positioning.

---

# Spacing System

Use a consistent spacing scale.

Never invent random spacing.

Every component should align to the same rhythm.

---

# Borders

Use subtle borders.

Borders separate.

They do not decorate.

Avoid thick borders.

Avoid bright borders.

---

# Border Radius

Minimal.

4px

8px

Maximum 12px

Avoid giant rounded cards.

This is not iOS.

---

# Shadows

Shadows should communicate elevation.

Not decoration.

Use soft shadows.

Avoid dramatic floating effects.

---

# Glass

Glassmorphism should be rare.

Only use glass when transparency improves hierarchy.

Never use glass because it looks modern.

---

# Buttons

Buttons should feel engineered.

Not playful.

Primary buttons:

Orange.

Secondary:

Dark.

Ghost:

Transparent.

Avoid excessive gradients.

Avoid pill-shaped buttons.

---

# Cards

Cards are not containers.

Cards are workspaces.

Each card should feel like:

A document.

A terminal.

A software module.

A notebook.

Not a floating rectangle.

---

# Icons

Use Lucide only.

One icon language.

Consistent stroke width.

No filled icons.

---

# Navigation

Navigation should disappear into the experience.

Avoid oversized navbars.

Avoid sticky elements unless necessary.

Navigation should feel lightweight.

---

# Images

Every image must communicate something.

Never add decorative screenshots.

Every screenshot should have purpose.

Compress all images.

---

# Videos

Videos should demonstrate.

Not decorate.

Autoplay only when muted.

Pause when offscreen.

Lazy-load.

---

# Animations

Motion should communicate.

Not entertain.

Every animation should explain:

Movement.

Relationship.

Hierarchy.

State.

Discovery.

---

# Hover States

Hover should reveal information.

Not surprise users.

Keep hover animations subtle.

Fast.

Responsive.

---

# Loading States

Never use blank pages.

Skeletons should resemble final content.

Avoid generic spinners.

---

# Accessibility

Contrast must exceed WCAG AA.

Focus states always visible.

Keyboard navigation supported.

Reduced motion respected.

Readable typography.

Semantic HTML.

---

# Mobile Philosophy

Mobile is not a smaller desktop.

Prioritize content.

Remove unnecessary interactions.

Avoid heavy WebGL.

Simplify layouts.

Maintain quality.

---

# Component Consistency

Buttons behave the same everywhere.

Cards behave the same everywhere.

Navigation behaves the same everywhere.

Spacing behaves the same everywhere.

Typography behaves the same everywhere.

Consistency builds trust.

---

# Design Principles

Every component should answer:

Why does it exist?

What information does it communicate?

Does it reduce cognitive load?

Can it be simplified?

Would removing it improve the page?

---

# Things Never To Do

Never use:

❌ Neon colors

❌ Rainbow gradients

❌ Glass everywhere

❌ Floating blobs

❌ Animated particles without purpose

❌ Skill bars

❌ Circular skill charts

❌ Technology logo walls

❌ Huge rounded rectangles

❌ Generic portfolio cards

❌ Fake terminal typing

❌ Auto-playing videos with sound

❌ Random background textures

❌ More than three accent colors

❌ Inconsistent spacing

❌ Inconsistent typography

❌ Decorative animations

❌ Visual effects that reduce readability

❌ Design trends copied without purpose

---

# Final Principle

The visitor should remember:

The engineering.

The projects.

The storytelling.

The interaction.

Not the colors.

Not the animations.

Not the UI framework.

If the interface becomes the most memorable part of the website,

the design has failed.
